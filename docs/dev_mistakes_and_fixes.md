## 2024/06/20

### 事例1：Razorビューの<option>タグでC#式を使いビルド失敗
- **ミス・問題**: Razorビュー（cshtml）の`<option>`タグで、`selected`属性にC#式（`@(条件 ? "selected" : null)`）を直接記述したため、RZ1031エラー（"The tag helper 'option' must not have C# in the element's attribute declaration area"）が発生し、ビルド失敗した。
- **原因**: Razorの仕様上、`<option>`タグの属性部分にC#式を直接書くことはできない。
- **解決策**: `selected`属性の出力は、if文で分岐してタグごと出力する形に統一する（例：`if (isSelected) { <option selected>...</option> } else { <option>...</option> }`）。

---

### 事例2：ビルド確認不足による動作検証の無駄
- **ミス・問題**: ビルド成功を十分に確認せず、動作検証を進めてしまった。
- **原因**: ビルドコマンドの出力やエラー内容を十分に確認しなかった。
- **解決策**: ビルドコマンド実行後は、必ずエラー・警告の有無を確認し、"Build succeeded." の明示的な表示をもって成功と判断する。

---

### 事例3：コマンド実行時のディレクトリ確認不足
- **ミス・問題**: コマンド実行時のディレクトリ確認が不十分だった。
- **原因**: コマンド実行前にカレントディレクトリを明示的に確認しなかった。
- **解決策**: コマンド実行時は、必ず`pwd`や`ls`等でカレントディレクトリを確認し、正しいディレクトリで実行する。

---

### 事例4：Razorフォームでname属性未指定によるバインド不全
- **ミス・問題**: Razorフォームで`asp-for`のみ使用し、明示的な`name`属性を付与しなかったため、POST時に値がバインドされず、ModelState.IsValidが常にfalseとなり、DB登録も画面遷移も行われなかった。以前の作業時間記録（TimeEntry）でも同様の問題が発生していた。
- **原因**: Razorの`asp-for`だけではname属性が正しく付与されない場合がある。モデルのプロパティがnullableでない場合、バインド不全時にバリデーションエラーとなる。
- **解決策**: input/select/textareaに明示的な`name`属性を追加。モデルのプロパティをnullable（string?）に統一。

## Razorファイルで@keyframes使用時のビルドエラーと解決策（2024/06/19）

### 問題内容
- Razorファイル（.cshtml）内で<style>タグ内にCSSアニメーションの@keyframesを記述した際、ビルド時に以下のエラーが発生：
  - `error CS0103: The name 'keyframes' does not exist in the current context`
- Razorのパーサが@keyframesをC#コードブロックと誤認識するため発生。

### 原因
- Razor構文では@記号がC#コードの開始と解釈されるため、CSSの@keyframesが正しく解釈されない。

### 解決策
- <style>タグ内の@keyframesを@@keyframesと記述することで、Razorがエスケープし、正しくCSSとして解釈される。
- 例：
  ```css
  <style>
  @@keyframes fadeInDown { ... }
  </style>
  ```

### 備考
- RazorファイルでCSSの@記号を使う場合は@@でエスケープするのが推奨。
